Callable 1 of 16: orchestrate_validation
Task 1: Validate ingested raw data structures and configuration parameters
(workbook line 5135)
================================================================================

(a) Inputs, Processes, Outputs

Inputs:
- loan_raw : pd.DataFrame — raw Lending Club Loan Data (Kaggle source).
- fraud_ecom_raw : pd.DataFrame — raw Fraud Ecommerce dataset (Kaggle).
- default_raw : pd.DataFrame — raw UCI Default of Credit Card Clients dataset
  (Yeh and Lien 2009).
- creditcard_raw : pd.DataFrame — raw Credit Card Fraud dataset (Dal Pozzolo
  et al. 2015).
- study_configuration : Dict — the single source of truth containing every
  paper-derived and replicator-chosen parameter.
- output_dir : Path — directory into which the validation reports are written.

Processes (executed in strict order):
1. Type-validate all six arguments (four DataFrames, dict, Path); fail fast.
2. Invoke validate_configuration (Task 1, Step 1.2) first: every paper-derived
   constant — dataset positive rates, feature counts, split fractions 0.60/
   0.20/0.20, scaling bounds (0.01, 10.01), pruning tolerance 0.01, P_max = 5,
   ECE bins B = 10, seeds [0,1,2,3,4], and the LLM-absence contract — is
   compared against hard-coded paper constants with tolerance 10^-10; the
   log-bound constant L = max{|log 0.01|, |log 10.01|} is recomputed, not
   trusted. The normalized configuration is returned.
3. Invoke validate_all_raw_schemas (Task 1, Step 1.1): per-dataset schema
   contracts (required columns with dtype assertions and alias resolution,
   e.g. raw_class/class, DEFAULT_NEXT_MONTH/default.payment.next.month),
   row-count lower bounds, per-column missingness proportions; SchemaValidationError
   on any failure; validation_report.json persisted.
4. Invoke validate_all_label_rates (Task 1, Step 1.3): direct positive-rate
   checks for FraudEcom (0.094), Default (0.221), Creditcard (0.0017) within
   +-0.001; for Loan, the {"Fully Paid", "Charged Off"} filter is applied and
   the filtered count (within 0.5% of 395,492) and rate (within 0.001 of
   0.101) are checked; LabelRateError with a full value_counts diagnostic on
   mismatch; label_check_report.json persisted.
5. Assemble the merged report {"config", "schemas", "label_rates"}.

Outputs:
- Dict with keys "config" (normalized configuration + config report),
  "schemas" (per-dataset schema report), "label_rates" (per-dataset label
  report), and the two persisted JSON reports under output_dir.
- Raises ConfigError / SchemaValidationError / LabelRateError on any breach.

(b) Input-to-output transformation
Four raw, unvalidated frames plus an unvalidated configuration are transformed
into a normalized, auditable configuration and three verified reports: the
configuration is normalized and frozen; raw frames are checked for schema
conformance; label columns are coerced to canonical strings and their
positive-class rates are checked against the paper's population contract. No
row is reordered, dropped, or mutated.

(c) LaTeX-context role
The paper's experimental setup defines the population contract this callable
enforces: "Each dataset is split into training, validation, and test sets
(60/20/20, stratified by label), repeated over five random seeds," over four
datasets summarized as "Creditcard 284,807 rows / 30 features / 0.17% positive
rate; FraudEcom 151,112 / 6 / 9.4%; Loan 395,492 / 42 / 10.1%; Default
30,000 / 26 / 22.1%," where "y = 1 denotes the minority risk class."

(d) Element of the research implemented
The schema-and-class-balance verification gate: every downstream task assumes
the paper's population, so the callable verifies feature counts, binary
labels, and base rates before any feature engineering. It is the fail-fast
entry point of the whole reproduction; the positive rates it locks are later
used as PR-AUC base-rate references ("we use the area under the precision-recall
curve (PR-AUC) as the primary performance metric and report the corresponding
base rate for reference").

Callable 4 of 16: orchestrate_splitting_and_scaling
Task 4: Stratified splitting and train-only min-max scaling
(workbook line 7375)
================================================================================

(a) Inputs, Processes, Outputs

Inputs:
- X : np.ndarray, shape (n, m) — feature matrix from Task 3.
- y : np.ndarray, shape (n,) — binary label vector.
- cfg : Dict — validated configuration (split fractions, seeds, bounds).
- dataset_name : str — artifact naming and imputation policy.
- feature_names : Sequence[str] — names aligned with matrix columns.
- seed : int — random seed for the stratified split.
- output_dir : Path — artifact archive root.

Processes:
1. Step 4.1 — make_stratified_splits: StratifiedShuffleSplit-based 60/20/20
   split (first 60/40, then 50/50 of the 40%), deterministic random state =
   seed, positive-rate check +-0.001 per partition, at-least-one-positive
   assertion; returns positional index arrays (train_idx, val_idx, test_idx).
2. Step 4.2 — fit_preprocessing on X[train_idx] ONLY: per-feature training
   medians (for remaining NaN columns such as revol_util, fico_midpoint),
   mins, maxs; constant-feature policy (denominator zero -> midpoint 5.01
   with warning); returns an immutable FittedPreprocessing container.
3. Step 4.3 — apply_preprocessing: impute validation/test NaN with training
   medians; apply the affine transform to all three partitions; clip
   out-of-range values to [0.01, 10.01] and record clip counts; assert the
   range and the log-bound constant L.
4. Persist splits (npz), fitted statistics (JSON with medians/mins/maxs/
   modes/constant policy/L/timestamp), and scaled matrices (npz) under
   versioned artifact directories.

Outputs:
- Dict with "splits" ({train, val, test} index arrays), "fitted"
  (FittedPreprocessing), "scaled" ({train, val, test} matrices), "clip_counts"
  (per-split counts), "persistence" (artifact paths).

(b) Input-to-output transformation
One un-split, unscaled matrix pair (X, y) becomes three disjoint scaled
partitions whose positive rates match the full data: rows are partitioned by
class stratum, statistics are fit on training rows only, and validation/test
rows are transformed exclusively by those training-derived statistics — the
leakage-safe preprocessing chain. The label vector is never transformed.

(c) LaTeX-context role
The paper prescribes the exact transform and split design: "features are
scaled to [0.01, 10.01], with the scaler fit on the training split only ...
repeated over five random seeds," and the derived worst-case bound constant
L = max{|log 0.01|, |log 10.01|} = 4.605170185988091 that the callable
recomputes and persists. Clipping maintains the bound's precondition that
every feature lie in the scaled range.

(d) Element of the research implemented
Stratified resampling (five seeds, 60/20/20) and min-max scaling with
leakage control, expressed as the affine transformation
\tilde{x}_j = 0.01 + 10.0 * (x_j - min_j) / (max_j - min_j),
with the log-feature bound L = max{|log \ell|, |log u|}. The scaled matrices
and split indices are the immutable inputs to training, pruning, threshold
selection, and calibration.

Callable 5 of 16: orchestrate_hyperparameter_search
Task 5: Optuna hyperparameter search on training splits
(workbook line 7830)
================================================================================

(a) Inputs, Processes, Outputs

Inputs:
- X_train : np.ndarray, shape (n_train, m) — scaled seed-0 training matrix.
- y_train : np.ndarray, shape (n_train,) — seed-0 training labels.
- cfg : Dict — validated configuration (search-space ranges, trial budget).
- dataset_name : str — study and artifact naming.
- output_dir : Path — artifact root.
- seed : int, default 0 — tuning seed (disambiguated once-per-dataset

1. If a hyperparameter record already exists for the dataset, load and return
   it (single source of truth; no re-search).
2. Otherwise run run_hyperparameter_search: Optuna study with direction
   maximize, TPESampler with fixed seed, MedianPruner, 100 trials; each trial
   samples eta log-uniform in [1e-4, 1e-1], lambda log-uniform in [1e-6,
   1e-2], epochs uniform integer in [100, 3000]; optuna_objective performs
   five-fold stratified cross-validation on the training split using the
   Task 6 core training routine, which stops on training-loss convergence
   (never on fold-validation PR-AUC, to prevent hyperparameter leakage); the
   objective returns mean fold PR-AUC.
3. Persist the study in SQLite (resumable) and the best configuration
   (eta*, lambda*, epochs*, best CV PR-AUC) as a checksummed JSON via
   persist_hyperparameters.

Outputs:
- Dict with "configuration" (the best-trial record) and "persistence"
  (JSON + study-database report).

(b) Input-to-output transformation
A training-only feature matrix and labels are transformed into a frozen
hyperparameter record: the cross-validated PR-AUC is the only selection
metric; the search trace and best configuration are persisted so every later
training run — across all five seeds — reuses the identical configuration.

(c) LaTeX-context role
The paper states: "Hyperparameters were optimized using Optuna on the
training split, with the best configuration selected by cross-validation."
The paper also supplies the three search axes' semantics: learning rate and
regularization govern the regularized logistic objective
\mathcal{L}(\alpha, \beta) = -(1/n) \sum_i [ y_i log \sigma(z_i) + (1 - y_i)
log(1 - \sigma(z_i)) ] + \lambda \sum_j |\beta_j|,
with epochs bounding gradient-descent training.

(d) Element of the research implemented
Bayesian hyperparameter search for the ECSEL monomial: selection of learning
rate, l1-regularization strength, and training length on the training
partition only, optimizing cross-validated PR-AUC — the paper's "primary
ranking metric for imbalanced classification."

Callable 6 of 16: orchestrate_monomial_training
Task 6: Train the full ECSEL single-term monomial
(workbook line 8479)
================================================================================

(a) Inputs, Processes, Outputs

Inputs:
- X_train : np.ndarray, shape (n_train, m) — scaled training matrix.
- y_train : np.ndarray, shape (n_train,) — binary training labels.
- hparams : Dict — selected hyperparameters from the Task 5 record.
- cfg : Dict — validated configuration (init values, convergence criterion).
- dataset_name : str, seed : int, output_dir : Path.
- X_val, y_val : Optional[np.ndarray] — validation partition used ONLY for
  post-training PR-AUC (no early stopping).

Processes:
1. Step 6.2 — train_monomial: initialize alpha = 1.0, beta_j = 0.1 for all j;
   precompute log X once; gradient-descent updates via automatic
   differentiation on the numerically stable log-space forward and the
   regularized loss; stop when the mean absolute relative training-loss
   change over 20 consecutive epochs is below 1e-6 or the epoch budget is
   exhausted; compute validation PR-AUC after training; record epoch count
   and convergence status in a TrainResult.
2. Step 6.3 — verify_trained_monomial: assert finite monomial outputs on a
   deterministic sample; assert the log-space identity to within 1e-6; log
   (not abort on) the smooth-loss gradient norm; record the support
   {j : |beta_j| > 0}.
3. Persist fitted parameters and the per-epoch loss history as JSON records
   with feature names and timestamps.

Outputs:
- Dict with "train_result" (TrainResult: alpha, beta, history, epochs_used,
  converged, val_pr_auc), "verification", "persistence".

(b) Input-to-output transformation
Scaled features and labels are transformed into a fitted, verified monomial:
the multiplicative model is trained in log-space for numerical stability, and
the fitted (alpha, beta) become the immutable inputs to pruning (Task 7),
the directional rule (Task 8), and the scorecard/tally (Task 9).

(c) LaTeX-context role
The callable implements the paper's core model:
z(x) = \alpha \prod_{j=1}^{m} x_j^{\beta_j},  P(y = 1 | x) = \sigma(z(x)),
its log-space identity
log|z(x)| = log|\alpha| + \sum_{j=1}^{m} \beta_j \log x_j,
and the regularized loss \mathcal{L}(\alpha, \beta) = -(1/n) \sum_i [ y_i
log \sigma(z_i) + (1 - y_i) log(1 - \sigma(z_i)) ] + \lambda \sum_j |\beta_j|,
"with sparsity regularization applied to the exponents" and parameters
"learned by gradient descent ... continuing until convergence of the training
objective."

(d) Element of the research implemented
ECSEL single-term monomial estimation via empirical risk minimization and
automatic differentiation, plus convergence/stability verification. The
verification of the log-space identity is one of the paper's mathematical
unit tests and guarantees that the interpretable decomposition into support,
direction, and magnitude is numerically exact.

Callable 7 of 16: orchestrate_pruning
Task 7: Post-hoc pruning and support-size selection
(workbook line 8952)
================================================================================

(a) Inputs, Processes, Outputs

Inputs:
- alpha : float — fitted coefficient from Task 6.
- beta : np.ndarray, shape (m,) — full fitted exponent vector.
- X_val : np.ndarray, shape (n_val, m) — scaled validation matrix.
- y_val : np.ndarray, shape (n_val,) — validation labels.
- cfg : Dict — validated configuration (tolerance 0.01, L).
- dataset_name : str, seed : int, output_dir : Path.
- feature_names : Sequence[str] — names aligned with matrix columns.

Processes:
1. Step 7.1 — evaluate_pruning_candidates: sort features by descending
   |beta_j| (tie-break ascending index); for each r = 1..m compute the
   pruned logit in log-space with a masked beta and the validation PR-AUC;
   record the full curve and the ranking order.
2. Step 7.2 — select_pruning_level: choose
   r* = min{ r : PR-AUC_val(r) >= PR-AUC_val(full) - 0.01 };
   if none, r* = m with a warning; record the retained set R and removed
   set R^c.
3. Step 7.3 — verify_pruning_bound: on validation rows (never test), compute
   the maximum realized gap
   max_x |s_full(x) - s_pruned(x)| and assert it does not exceed
   L * sum_{j in R^c} |beta_j|; abort on violation beyond 1e-6.
4. Persist the support record (with retained names and exponents) and the
   per-r PR-AUC curve as JSON artifacts.

Outputs:
- Dict with "curve", "support", "bound_verification", "persistence".

(b) Input-to-output transformation
A full fitted monomial plus validation data are transformed into a pruned
monomial: the exponent vector is reduced to the smallest support whose
validation PR-AUC stays within tolerance, and the worst-case perturbation
bound is empirically verified on the validation sample before the support is
consumed by every downstream simplification.

(c) LaTeX-context role
The paper's Remark states the exact bound the callable verifies: "With
features scaled to [\ell, u], 0 < \ell, and L := max{|log \ell|, |log u|},
the log-scores before and after pruning satisfy
|s_full(x) - s_pruned(x)| = |\sum_{j in S} \beta_j \log x_j| <= L \sum_{j in S}
|\beta_j|, for every x." The paper adds: "we therefore choose r on validation
data as the smallest value whose PR-AUC remains within a fixed tolerance of
the full monomial" — the exact selection rule implemented.

(d) Element of the research implemented
Post-hoc pruning by exponent magnitude with support-size selection on the
validation partition, justified as the worst-case-optimal criterion by the
triangle-inequality bound, and verified as a mathematical unit test. The
paper's empirical claim "pruning is nearly free" (max PR-AUC loss 0.008) is
produced by this callable's downstream evaluation.

Callable 8 of 16: orchestrate_directional_rule
Task 8: Directional rule construction and closed-form fidelity prediction
(workbook line 9365)
================================================================================

(a) Inputs, Processes, Outputs

Inputs:
- alpha : float, beta : np.ndarray (m,) — fitted monomial parameters.
- retained : Sequence[int] — retained feature positions from Task 7.
- X_train, X_val, X_test : np.ndarray — scaled matrices (train used ONLY for
  the covariance; val/test for scores).
- cfg : Dict; dataset_name : str; seed : int; feature_names : Sequence[str];
  output_dir : Path.

Processes:
1. Step 8.1 — build_directional_rule: construct d_j = sign(beta_j) for j in R
   and 0 otherwise; compute the directional score
   s_dir(x) = \sum_{j in R} sign(beta_j) log x_j on validation and test;
   produce the natural-language mapping (high/low increases risk) from the
   sign of alpha * beta_j.
2. Step 8.2 — predict_fidelity: on the TRAINING log-feature matrix only,
   compute the sample covariance (n-1 denominator), the Pearson correlation
   rho = (beta^T Sigma d) / (sqrt(beta^T Sigma beta) sqrt(d^T Sigma d)),
   clip |rho| > 1 numerically with a logged event, and apply Greiner's
   relation tau_pred = (2/pi) arcsin(rho).
3. Step 8.3 — record_fidelity_predictions: persist rho, tau_pred, the
   retained support, and the sign vector BEFORE any held-out evaluation of
   the directional rule.

Outputs:
- Dict with "d", "scores" ({val, test}), "rule_mapping", "prediction"
  (rho, tau_pred), "persistence".

(b) Input-to-output transformation
The fitted exponent vector and retained support are transformed into a
sign-flattened scoring rule and a closed-form a-priori fidelity prediction:
magnitudes are discarded, directions retained, and the predicted rank
fidelity is derived purely from fitted exponents and training covariance —
no directional-rule evaluation is required.

(c) LaTeX-context role
The paper's Proposition is the governing mathematics: "Up to constants, the
full and directional log-scores are the linear functions s_full = beta^T w
and s_dir = d^T w ... Their correlation is
rho = (beta^T Sigma d) / (sqrt(beta^T Sigma beta) sqrt(d^T Sigma d)), which
holds without distributional assumptions. If w is elliptically distributed,
Greiner's relation links this correlation to the rank fidelity between the
two scores: tau = (2/pi) arcsin(rho)." The paper notes the prediction "can be
estimated before the simplified rule is produced" — the callable's defining
property.

(d) Element of the research implemented
Directional-rule construction and closed-form fidelity prediction: the only
simplification whose expected agreement with the original classifier is
computable immediately after training, before the rule is even evaluated.
The paper's Table (rho, tau_pred, tau_b, MAE) — with MAE 0.017 on Loan/
Default/Creditcard and 0.236 on FraudEcom (tie-sensitive failure) — is
generated from this callable's records.

Callable 9 of 16: orchestrate_scorecard_tally
Task 9: Scorecard and tally construction with validation-threshold selection
(workbook line 9823)
================================================================================

(a) Inputs, Processes, Outputs

Inputs:
- alpha : float, beta : np.ndarray (m,), retained : Sequence[int] — fitted
  monomial and pruned support.
- X_train, X_val, X_test : np.ndarray — scaled matrices (train used ONLY for
  median cutpoints).
- y_val, y_test : np.ndarray — validation and test labels.
- cfg : Dict; dataset_name : str; seed : int; feature_names : Sequence[str];
  output_dir : Path.

Processes:
1. Step 9.1 — build_binary_conditions: for each retained feature, the
   training median c_j is the cutpoint; the risk-increasing side follows the
   sign of alpha * beta_j; indicators are
   1_j(x) = I[x_j >= c_j] if alpha*beta_j > 0, else I[x_j <= c_j];
   indicator matrices are produced for validation and test.
2. Step 9.2 — assign_scorecard_points:
   p_j = max(1, round(5 * |beta_j| / max_k |beta_k|)) with P_max = 5;
   scorecard_score computes V(x) = \sum_j p_j 1_j(x); tally_score computes
   T(x) = \sum_j 1_j(x) for validation and test.
3. Step 9.3 — select_thresholds: enumerate all integer thresholds v in
   {1..sum p_j} and t in {1..|R|}; maximize validation F1 (the
   replicator-chosen decision metric); apply the selected thresholds to the
   test split, producing binary predictions.

reliable probability estimates: the validation-fit isotonic map is applied
unchanged to test scores, and the mean absolute bin-wise discrepancy between
observed positive frequency and mean predicted probability is reported.

(c) LaTeX-context role
The paper prescribes the mechanism and the metric: "we calibrate each
representation on the validation set using isotonic regression and report
